循环队列的三种判空、判满方法，有什么区别？
ASSISTANT / 01

三种方法，一张表看懂

当队头与队尾重合时，需要额外的规则区分“空”和“满”。不同方法的主要差异，在于空间利用与状态维护。

方法空间开销特点
牺牲一个单元一个存储单元实现简单
记录 size一个整数状态直观
设置 tag一个标志利用全部容量

01 · 牺牲一个存储单元

预留一个位置，让队尾的下一个位置与队头重合时表示队满。这样，队头和队尾相等就只代表空队列。

判断条件

队空：front == rear
队满：(rear + 1) % maxSize == front

适合什么时候使用

当实现简单比容量利用更重要时，这个方法很方便。容量很大的队列中，一个位置的损失通常不明显。

02 · 记录元素个数 size

额外记录当前元素数量，每次入队加一、出队减一，判空和判满都可以直接比较数量。

判断条件与维护

元素数为零时为空，等于容量时为满。每次修改队列，都要同步维护计数。

03 · 增加状态标志 tag

当队头与队尾重合时，根据最近一次操作区分空与满。标志的含义需要保持统一，避免遗漏更新。

怎样选择更合适

优先看需求：实现复杂度、容量是否紧张，以及是否需要经常查询元素个数。

三种方法的常规入队、出队操作都能达到常数时间复杂度，不能仅凭多一条赋值就判断复杂度发生变化。

如果容量固定且很小，应该重点考虑什么？
ASSISTANT / 02

先看容量利用率

对于只有少量单元的队列，预留一个单元所占的比例较大，可以考虑计数或标志位方案。

再看维护成本

如果需要随时读取当前队列长度，计数法更直接；如果只需要空满状态，标志位方案也可以满足需求。

帮我用一句话记住。
ASSISTANT / 03

预留位置最简单，记录数量最直观，维护标志可用满容量。
